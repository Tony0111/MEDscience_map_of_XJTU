## #01 用 Zotero 中转生成中间 CSV

**状态**：✅ 已修复（`notebooks/01_parse_nbib.ipynb`）

**现象**

原始 `.nbib` 数据先导入 Zotero，再导出成 CSV 才交给 Python。其实 Python 可以直接读 `.nbib`，Zotero 这一步没必要，还带来信息损失——比如 MeSH 主题词和作者关键词被合并在一起，PMID 也被替换掉了。

**影响**

- 流程不可复现，中间多了一个人工操作环节。
- 导出的表列多、噪音大。
- MeSH 受控词与作者关键词混为一谈，影响关键词分析的结论。

**建议**

直接用 Python 解析原始 `.nbib` 得到干净的中间数据，去掉 Zotero 环节。

**修复**

`01_parse_nbib.ipynb` 直接解析 `data/raw/pubmed-XJTU-*.nbib`：
按 MEDLINE「标签 - 值 + 续行」规则解析，逐条提取 `FAU/AUID/AD/MH/OT/PT/...`，
按 `PMID` 去重后输出 `data/interim/articles.csv`（`mesh` 与 `keywords` 分列保存）。

## #02 作者姓名规范化不适用中文名

**状态**：✅ 已修复（规则版，`notebooks/01_parse_nbib.ipynb` 第八步）

**现象**

作者规范化只保留“姓 + 名首字母”（把很多不同的人统一成 `Zhang Y` 这种形式），中文名重名率极高，大量不同作者被当成了同一个人。

**影响**

- 高产作者统计严重失真（出现“发文两千多篇”的假作者）。
- 建立在作者基础上的合作网络不可信。

**建议**

换更可靠的作者消歧方式（结合单位、邮箱、ORCID 等），或明确声明作者维度的分析不适用。

**进展**

`01_parse_nbib.ipynb` 额外输出 `data/interim/authors.csv`（长表：`pmid, seq, full_name, orcid, affiliations`），
并给每个作者条目分配一个稳定的 **`author_key`**（`articles.csv` 里对应 `authors_key`）：

- 有 ORCID → `orcid:0000-...`（全球唯一，最可靠）；
- 没有 ORCID → `name:<规范化全名> @ <规范化单位>`（取第一个单位）。

这样**同名但不同单位**的人（如两位 `Wang, Kai`）会被分开，旧版“`Zhang Y` 发文两千篇”的虚高被消除。

**残余局限（留给 02 检查）**：改名、跨单位调动、同名同单位仍会误判；ORCID 覆盖率约 44.7%，
所以无 ORCID 的作者可能被过度拆分。作者维度的结论需结合这些局限说明。
